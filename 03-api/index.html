    光照测量 API 文档案例

    这个项目是什么

    这是一个面向 IoT 开发者的模拟 REST API 文档案例。在这个具体场景中，开发者已经拿到设备编号和 Access Token，需要读取某台设备最近一次成功保存的光照数据，再确认设备编号、采集时间和光照度是否符合预期。

    项目分成三个页面。概览说明文档怎样分工，使用指南带读者完成第一次请求，API Reference 集中提供开发和排查时需要反复查询的接口定义。三个页面围绕同一条 Endpoint 展开。

    GET /devices/{device_id}/measurements/latest

    项目边界

    这个案例没有连接真实服务或硬件。域名、设备编号、Access Token、响应数据和频率限制都属于示例。目前完成的是页面结构、接口契约和三篇文档之间的一致性核对，尚未完成真实请求测试。

    包括哪些文档

    • 项目概览：说明项目内容、接口范围和三篇文档的一致性。
    • 使用指南：带读者准备调用信息、发送第一次请求、检查响应并处理错误。
    • API Reference：集中说明 Endpoint、认证、参数、响应字段、错误码、频率限制和数据约定。

    一次请求怎样走完

    使用指南从三个准备项开始。Base URL 指向示例环境，Device ID 指定要查询的设备，Access Token 用于 Bearer Token 认证。读者把占位值换成自己的值后，发送一条 GET 请求。

    请求返回 HTTP 200 时，响应里的四个字段的作用分别为：

    • device_id 用来确认返回结果属于目标设备。
    • measured_at 用来判断这条数据是否足够新。
    • illuminance_lux 给出以 lux 为单位的光照度。
    • request_id 用来关联这次请求和服务端日志。

    一次 GET 请求结束以后，接口不会继续推送后续变化。历史记录、分页、WebSocket 和 SSE 也没有混进当前页面。

    两篇子文档怎样对应

    使用指南负责带读者做完一次调用，API Reference 负责把同一组信息写成可查询的契约。两篇页面使用相同的名称、示例值和错误定义。

    核对项 使用指南 API Reference
    Endpoint 给出可直接修改的 curl 请求 定义路径和 device_id 约束
    认证 说明 Bearer Token 的写法 定义 Authorization 请求头
    成功结果 按顺序检查四个响应字段 定义字段类型、是否为空和取值约束
    数据时间 提醒读者判断数据是否足够新 规定 measured_at 使用 RFC 3339 和 UTC
    调用失败 给出每类错误的恢复动作 定义 HTTP 状态码、业务错误码和触发条件
    请求追踪 提醒读者保存 request_id 在成功和失败响应中都定义追踪编号

    这张表也给文档校对留下了清楚的检查路径。使用指南里出现的字段，能在 Reference 中查到；Reference 中定义的错误，读者也能在使用指南里找到能执行的下一步。

    几个具体取舍

    最新数据只返回一条

    /measurements/latest 固定返回一条记录，因此没有查询参数，也不接受 limit、排序或分页参数。这样一来，页面标题、Endpoint 和响应含义说的是同一件事。

    Token 只写到当前调用需要的位置

    两篇子文档都假定开发者已经取得 Access Token。当前案例没有 Token Endpoint、授权类型、Scope、有效期和刷新规则，继续补写会让示例看起来可以执行，实际却没有可用的认证服务。

    页面只说明已经确定的部分。请求必须携带 Authorization Header，值采用 Bearer <token> 格式。401 用于认证失败，403 用于凭证缺少设备读取权限。

    两种 404 分开处理

    设备编号不存在和设备尚未上报数据，都会得到 HTTP 404，下一步却完全不同。DEVICE_NOT_FOUND 要求开发者换成实际设备编号，MEASUREMENT_NOT_FOUND 要求等待设备产生数据后再试。

    把这两个结果拆开以后，错误码才能真正帮读者决定下一步。

    字段要接得住后续动作

    这组文档里，我更在意字段能不能接住读者的下一步。measured_at 用来判断数据新鲜度，request_id 用来追踪问题，Retry-After 告诉调用方在 429 后要等多久。字段列出来只是第一步，它还要在使用指南里被真正用到。

    当前完成到哪里

    项目概览与两篇子文档统一使用同一条 Endpoint。使用指南和 API Reference 采用相同的示例设备编号、响应字段、错误码和数据约定。时间采用 RFC 3339 格式并返回 UTC，光照度统一使用 lux。API Reference 还定义了每个 Access Token 每分钟 60 次请求的示例限制，以及 429 响应中的 Retry-After。

    这些内容仍然是一份模拟接口契约。curl 命令不能连接真实服务，认证、权限、频率限制和错误响应也没有经过请求测试。OpenAPI 文件、Mock API、Token 管理、设备管理和历史数据接口都不在当前交付范围内。
