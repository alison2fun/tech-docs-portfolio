# 微步 ACTION 系统流程设计

本页根据 PRD 整理产品的流程设计，用于说明从接收用户输入、生成任务结果，到记录任务推进状态的整个路径。

## 设计中的组件

| 组件 | 设计职责 |
| --- | --- |
| 小程序前端 | 接收任务输入，展示步骤、勾选状态和进度变化 |
| 微信云函数 | 接收任务描述，组织拆解请求，返回步骤结果 |
| DeepSeek | 根据任务描述生成 5 个行动步骤 |
| 微信云开发数据库 | 在 `tasks` 集合中保存任务内容、步骤状态和完成进度 |

## 一次任务拆解怎样流动

这条路径设计为：

```text
用户输入任务
→ 小程序前端接收输入
→ 微信云函数接收任务
→ DeepSeek 生成 5 个步骤
→ 微信云函数返回结果
→ 小程序展示任务卡片
→ 任务结果写入 tasks 集合
→ 用户勾选步骤
→ 页面更新进度和任务状态
```

## 各组件怎样分工

### 小程序前端

负责：

- 接收任务描述；
- 提示用户补充时间、目标和限制；
- 展示 5 个步骤；
- 处理勾选动作；
- 显示完成百分比和进度条。

正式实现时，还要继续补输入校验、加载状态、失败提示和状态恢复。

### 微信云函数

微信云函数把前端输入和 DeepSeek 返回的结果接起来。

它至少需要处理三件事：

- 接收任务描述；
- 把任务组织成适合拆解的请求；
- 返回结构稳定的步骤结果。

前端调用方式和失败情况见[任务拆解云函数调用说明](task-decomposition-interface-draft.md)。

### DeepSeek

DeepSeek 负责把一句任务描述转换成 5 个行动步骤。

真正落地时，还需要进一步明确：

- 使用哪个模型版本；
- 怎样写提示词；
- 超时和失败怎样返回；
- 哪些字段需要回传给前端。

### 微信云开发数据库

`tasks` 集合保存的内容包括：

- 任务名称；
- 步骤清单；
- 提示内容；
- 每一步是否完成；
- 当前完成数和进度。

当前代码没有设置任务记录的自动过期时间，也没有提供由用户主动删除单条任务记录的入口。账号怎样和任务关联、记录怎样清理，仍然属于后续需要继续明确的边界。

## 数据怎样变化

| 阶段 | 数据 |
| --- | --- |
| 用户输入 | 任务描述、时间和当前限制 |
| 拆解请求 | 微信云函数整理后的任务内容 |
| 生成结果 | DeepSeek 返回的 5 个行动步骤 |
| 数据保存 | 任务名称、步骤、提示内容和完成状态写入 `tasks` 集合 |
| 页面展示 | 步骤内容和完成状态 |
| 用户勾选 | 步骤状态从未完成变为已完成 |
| 进度更新 | 完成数量和百分比变化 |

## 失败时需要处理什么

正式实现时，至少要处理这些情况：

- 输入内容过于模糊；
- 输入为空；
- 网络中断；
- DeepSeek 超时；
- 返回结果不是 5 个可执行步骤；
- 勾选后进度没有更新；
- 页面刷新后状态没有恢复。

这些情况看起来像边角问题，但它们会直接影响用户对产品的判断。如果一件事刚开始推进，就在这里断掉，用户下次很可能就不会再回来。
