# 微步 ACTION 原型迭代记录

本文档记录微步 ACTION 已经完成的产品和文档工作。

尚未完成的功能与判断，统一放在[产品路线图](roadmap.md)。

## 第一阶段：把任务拆解路径画出来

第一版原型先完成了最核心的一条路径：

```text
输入任务
→ 生成 5 个步骤
→ 勾选已经完成的步骤
→ 查看进度变化
→ 完成全部任务
```

这一阶段完成了：

- “新行动”任务输入页；
- 5 步任务卡片；
- 步骤勾选状态；
- 完成数量和进度条；
- 任务完成弹窗；
- 成就箱和任务详情界面。

最初的重点，是确认用户能不能看懂“任务被拆开以后，要怎样继续做”。

## 第二阶段：接入真实任务拆解

原型随后接入微信云函数 `generatePlan`。

前端把用户输入的任务传给云函数，云函数调用 DeepSeek 的 `deepseek-chat` 模型，要求模型返回 5 个行动步骤和 2 条提示。

这一阶段完成了：

- 前端云函数调用；
- DeepSeek 请求；
- JSON 格式结果约束；
- 任务步骤和提示内容返回；
- 生成结果在小程序页面中展示。

任务拆解从静态界面，进入了可以真实发起请求的流程。

## 第三阶段：保存任务和进度

项目使用微信云开发数据库保存任务记录。

`tasks` 集合中已经包含：

- 任务名称；
- 行动步骤；
- 提示内容；
- 创建时间；
- 步骤完成状态；
- 整个任务是否完成。

成就箱会读取任务记录，展示已完成和仍在推进中的任务。用户重新打开任务详情后，可以继续处理之前生成的步骤。

这一阶段把“生成一次结果”扩展成了“任务可以被继续推进”。

## 第四阶段：重构产品文档

2026 年 7 月，我重新整理了微步 ACTION 的文档结构。

把原来放在同一页里的各种内容，拆成了按读者和任务组织的文档集，包括：

- 产品概览；
- 原型快速体验；
- 创建与拆解任务；
- 管理任务与进度；
- 常见问题；
- 输入内容安全提醒；
- 产品需求文档；
- 系统流程设计；
- 云函数调用说明；
- 数据与隐私边界；
- 原型迭代记录；
- 产品路线图。

这次重构也暴露了几项此前没有认真处理的问题：

- 用户不能主动删除任务；
- 数据没有自动过期；
- 数据库权限和用户隔离仍需核对；
- 错误提示和失败恢复不够完整；
- 部分页面能力已经存在，但文档仍停留在原型描述。

## 当前状态

目前已经形成了下面这条真实链路：

```text
任务输入
→ generatePlan 云函数
→ DeepSeek 生成步骤
→ 页面展示任务并保存任务记录
→ 用户勾选步骤
→ 云数据库更新任务进度
→ 成就箱读取历史记录
```

下一阶段不再继续扩写文档类型，优先补齐数据控制、错误处理和运行验证。
